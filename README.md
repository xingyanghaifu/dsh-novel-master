# dsh-novel-master · 小说创作大师

为 DeepSeek Harness（DSH）提供小说写作、分析、项目管理和智能辅助工具。当前包含 30 个功能命令及 1 个更新维护命令。

## 安装

在 DSH 的「设置 → 插件」中选择 GitHub 来源，填写：

```text
github:xingyanghaifu/dsh-novel-master
```

启用 bundle。此项目通过 GitHub 分发；不要在 npm 来源里仅填写包名。需要宿主提供 commands 服务和 @deepseek-ai/schemastery。goals 服务可选：有 goals 时可以持续执行写作目标，否则每轮写作后等待继续。

## 配置与更新

配置页位于「设置 → 小说创作大师」，提供总开关、按写作/规划/分析/项目管理/智能辅助分组的命令开关、组内启停、全选/全关及当前启用数量。命令批量选择只修改命令项，学习和决策引擎还有各自总开关。开关保存后按差异注册/移除命令，无需重启。关闭插件总开关会移除功能命令并停止智能处理，仍保留配置和更新维护入口；已经运行的写作目标可用 `/goal pause` 暂停。在插件管理器禁用整个 bundle 则卸载全部入口。

配置页分为「功能选择」「引导模型」「学习总结」「决策助手」「资料检索」「批量写作」「更新维护」七个页签。顶部汇总当前版本、命令选择和引擎状态；功能区支持关键词搜索与常用组合。页面只根据实际返回配置显示状态，接口暂不可用时提供重试和明确诊断。Web 服务延迟启动或被替换时，插件会等待并重新挂载接口。

按次计费模型请用「批量写作」页签：`/novel-batch` 把上下文整批内联进**一次**模型请求，模型按分隔标记连续输出多章，插件自己拆分落盘，因此一章不额外消耗请求。`--每批N章` 或配置项「每次请求章数」决定每批章数，章数越多请求次数越少。加 `--auto` 会按同一批大小反复请求直到达到目标章数：该循环在当前命令内执行，所以随时可取消，回执也报告真实写入章数与真实请求次数（例如 60 章、每批 6 章约 10 次请求），而不是只回报「已提交」。进度写入项目内 `批量写作状态.json`。提供方与模型都留空时使用本会话最近一次实际请求路由；两者都未确定时命令直接报错，不会猜测模型或把内容发到别的模型上计费。输出上限仍由模型自身决定：模型提前截断导致缺少分隔标记时，该批不会写入任何文件，`--auto` 也会就此停止并报告已完成的部分，不会继续扣费重试。

资料检索默认关闭，不会在关闭时访问网络或创建存储目录。打开后必须明确填写已注册的 Provider 和 Model，插件才注册 `/novel-research`。命令先通过宿主 `web` 服务检索并抓取来源，再把带 URL 的来源材料交给选定模型；模型只能依据这些材料返回事实、数据、引用、局限和逐条模型自评置信度（高/中/低及 0 到 1 数值，非独立核验）。搜索或抓取失败会被标记，来源不足时不生成结论，不把模型记忆当作资料。默认将原始检索记录、来源正文和 Markdown 报告保存到工作目录 `novel_research`，也可在设置页指定资料存储目录；切换目录不会迁移旧记录。该目录中的 JSON 适合程序复核，Markdown 适合人工阅读。

来源参考分仅按域名类别、发布日期和抓取状态作 60%/30%/10% 加权，不验证事实、不自动排序或筛选来源；所有事实和结论仍需人工核验。`/novel-trends` 仅展示 6 个静态题材样例，7d/30d/90d 使用相同数据，不查询实时市场来源，也不提供市场入场建议。

项目目录默认为 `novel_projects`，可改成 `books/novels` 等工作目录内的相对路径。新调用使用新目录，已有任务保留原路径；不会自动搬迁项目。每次命令拥有独立目录快照，并发会话不会串目录。绝对路径和 `..` 等不合法路径会被拒绝。

⚠️ **项目目录配置问题？** 如果遇到路径相关错误，请参考 **[项目目录配置故障排查指南](TROUBLESHOOTING_PROJECT_DIR.md)**，了解详细的配置规则和修复方法。

更新入口参考 Our Free Model 的检查/拉取流程：检查固定 GitHub 仓库的最新提交，拉取时交给 DSH 插件管理器安装该确定提交，而不是直接覆盖运行中的文件。不保存 GitHub 令牌，也不自动批准依赖安装脚本。

直连 GitHub 超时时，可在设置页填写「更新检查代理」，例如本地代理 `http://127.0.0.1:7897`。该地址只是示例，请使用自己实际的代理端口；留空使用 `HTTPS_PROXY` / `HTTP_PROXY` 或直连。安装下载沿用 DSH 插件管理器网络设置。代理设置可热更新，不修改整个 DSH 的全局网络配置。

```text
/novel-update check
/novel-update apply
/novel-update reload
```

更新结果区分安装成功、代码重载、需要重启和失败。安装成功后会尝试代码热重载；也可以点「重载插件」或执行 `reload`。兼容性适配层只在宿主提供已识别的 Loader/cache 能力时切换运行实例，失败时尝试恢复旧缓存与实例并报告恢复状态，不支持的宿主会明确要求重启。新增客户端页面首次加载仍可能需要重启；界面代码更新后可刷新当前页面。配置热更新与插件代码更新属于不同操作。

## AI 小说资产生成

插件内置**生图工作台**（右侧栏独立页签），可生成并管理四类资产：角色立绘、场景地图、物品道具、**世界地图底图**。

三步流程：① 一句话描述 → 对话模型扩写成提示词 → ② 生图模型生成 → ③ 绑定到具体资产。支持上传参考图（垫图），密钥与地址在「设置 → AI 生图」中独立配置，所有请求由宿主进程发出，无需跨域代理。

绑定世界地图底图后，图片会铺在设定树地图的矢量层下方，可一键切换「叠加矢量层 / 只看底图」。

详见 **[地图底图绑定使用指南](docs/map-asset-guide.md)**。

## 自主学习与决策 AI

在设置页打开「学习总结」，分别选择自动总结与历史经验复用。学习默认关闭；打开后只处理明确由小说命令提交的任务。自动总结使用已成功提交的助手结果，从该结果读取实际 provider/model；不会把会话标题、压缩摘要、辅助模型调用或其他会话当成小说成果。长篇写作绑定具体小说目标，后续轮次只有该目标仍处于激活状态时继续跟踪；普通任务只接受本次完成结果。

默认存储地址为工作目录下 `novel_learning`，也可填写绝对地址。目录结构按工作目录哈希、provider/model 的安全名称与原始身份哈希隔离。同名显示名称、斜杠与大小写差异不会互相覆盖。切换地址后不会自动搬迁旧记录。每条记录包含时间、来源项目/会话、归属模型和实际生成摘要的模型；不写入原始会话或隐藏推理。

摘要模型 provider/model 全部留空时使用被总结输出的模型；也可填写另一组完整路由，记录仍归属原来源模型。默认总结输入最多 12000 字符、每个模型命名空间最多 500 条记录、自动总结间隔 60 秒。达到记录上限时停止追加并报告，不自动删除用户数据。智能模型调用最多四个并发，消息核对队列最多十六项；繁忙时自动总结跳过并记录状态，可稍后手动学习。摘要是模型生成的经验建议，不代表已验证的质量提升，也不修改模型权重。

```text
/novel-learn 项目名
/novel-memory 项目名
/novel-decide 主角应如何进入秘境？ | 公开身份换取资格 | 隐瞒身份加入探险队
```

手动学习读取所选项目最近最多三章的有界内容，或该模型最近完成的小说回复。手动学习、记录查询及任务开始时的经验复用采用会话日志中最后观察到的请求/回复模型路由；它不保证未来请求不会被路由到另一模型。身份未知时明确提示或跳过，不拿全局默认模型替代。复用经验以可见任务参考加入当前会话，绝不暗中改写宿主冻结的模型请求。

在设置页打开「决策 AI」，明确填写已注册 provider 与 model，可指定模型支持的推理强度、人工复核置信度阈值和超时。启用后提供真实 `novel_decide` 模型工具，写作提示要求在适合自主决策的剧情分岔或审校取舍处调用；用户要求亲自选择时仍尊重用户。工具仅对已提交的小说任务开放，也可用上面的手动命令直接发起建议。关闭该功能或单独关闭 `decide` 命令会撤下工具。

决策模型只能在给定选项中选择，返回简短依据、置信度和人工复核标记。低于配置阈值、模型要求复核、调用失败、超时或结果非法时交给用户处理。建议不会授予删除、覆盖、恢复或发布权限。决策记录保存在同一隔离存储中，并单独标注决策模型；来源模型未知时标记为未知，不冒充会话模型。决策引擎独立启用时也会保存审计记录，学习总开关只控制学习总结与复用。

设置页的「读取学习与决策活动」可查看真实工作状态、写入统计、存储位置和最近错误。存储为独立原子记录文件，拒绝符号链接、硬链接和不安全路径；写入锁发生崩溃残留时会报告锁地址，需要检查后处理，不自动抢占。完整执行提示和验收要求见 [智能能力扩展要求](docs/INTELLIGENCE_REQUIREMENTS.md)。

## 模型工具

除斜杠命令外，插件把可以安全自动化的能力注册为模型工具，方便模型或其它插件编排：

| 工具 | 作用 | 是否写文件 |
|---|---|---|
| `novel_projects` | 列出所有项目、章数、字数 | 只读 |
| `novel_status` | 单项目进度：章数、字数、平均章长、缺失的设定文件 | 只读 |
| `novel_read` | 读设定文件（设定/角色/大纲/世界状态/伏笔/剧情树/写作规范/地区/事件/脑洞/项目.json） | 只读 |
| `novel_chapter_read` | 列章节清单，或读单章正文（超长自动截断） | 只读 |
| `novel_decide` | 剧情/审校/学习建议决策 | 只存审计记录 |
| `novel_probe` | 单次输出上限实测 | 不写项目文件 |
| `novel_batch` | 批量写章节 | 写正文 |

只读工具刻意保持只读：会改动正文的命令（`/novel`、`/novel-continue`）没有暴露成工具，避免模型编排时悄悄改写项目文件。`novel_read` 的文件名走白名单校验，`../` 之类的路径穿越会被拒绝。

## 命令

参数中的 `[项目]` 可省略，默认使用当前目录下最近更新的项目。涉及文件导入的相对源文件路径仍以会话工作目录为基准。

| 命令 | 用途 |
|---|---|
| `/novel <脑洞> [60章\|20万字] [--auto]` | 建项目并提交规划、写作和收尾目标 |
| `/novel-continue [项目\|文件.txt] [N章] [--auto]` | 续写项目或导入 TXT/Markdown（支持 GBK） |
| `/novel-chapter [项目] <章号> [要求]` | 请求生成指定新章节，避免静默覆盖已有章 |
| `/novel-batch [项目] [N章] [--每批20章] [--auto] [要求]` | 一次模型请求连续写多章，按次计费模型最省请求 |
| `/novel-rewrite [项目] <章号> [要求]` | 请求改写，要求先保留旧稿 |
| `/novel-idea <脑洞>` | 请求展开多个构思方向 |
| `/novel-outline [项目] [要求]` | 请求生成或调整大纲 |
| `/novel-cast [项目] [要求]` | 请求生成角色档案 |
| `/novel-world [项目] [推演要求]` | 直接查看世界状态；有要求时提交世界推演任务 |
| `/novel-role [项目] [角色名\|要求]` | 查看角色，或提交修改任务 |
| `/novel-spark [项目] [卡点]` | 请求下一步剧情建议 |
| `/novel-study <参考文件> [--to 项目]` | 统计参考文本并请求风格分析 |
| `/novel-review [项目] [章号\|最近N章] [--deep]` | 请求基础或深度审校 |
| `/novel-conflict [项目] [章号\|N-M]` | 请求冲突分析 |
| `/novel-pace [项目]` | 请求节奏分析和文字图示 |
| `/novel-reader [项目] [章号\|N-M] [--persona 类型]` | 请求模拟读者反馈 |
| `/novel-dialogue [项目] <章号> [角色名]` | 请求对话检查与改写建议 |
| `/novel-emotion [项目] [章号\|N-M]` | 请求情感变化分析 |
| `/novel-market <平台> [项目]` | 根据平台经验请求适配建议 |
| `/novel-compare ...` | 请求对比两份作品或章节，具体参数见命令提示 |
| `/novel-tips ...` | 请求针对写作问题的技巧与示例 |
| `/novel-trope ...` | 请求套路设计、变体及风险分析 |
| `/novel-stats [项目] [--detailed]` | 直接计算字数、章数、进度、伏笔与详细统计 |
| `/novel-export [项目] [txt\|md\|html]` | 直接导出整书及目录 |
| `/novel-backup ...` | 创建快照、列出快照、恢复预览/执行及差异比较 |
| `/novel-merge ...` | 将选定章节合为新文件，保留源文件 |
| `/novel-split ...` | 将选定章节分成新文件，保留源文件 |
| `/novel-learn [项目]` | 由模型总结最近正文或小说任务输出并保存经验 |
| `/novel-memory [项目]` | 查询同模型的学习与决策记录及实际存储位置 |
| `/novel-decide 问题 \| 选项A \| 选项B` | 调用指定模型在候选项中给出建议与复核要求 |
| `/novel-update check\|apply\|reload` | 检查、拉取固定提交更新及重载代码 |

```text
/novel-compare "参考作品.txt"
/novel-chapter 4-6 --length 2500 --style 轻松
/novel-chapter 1 --draft
/novel-backup create
/novel-backup list
/novel-backup restore <ID>
/novel-backup restore <ID> --apply
/novel-backup diff <ID>
/novel-merge 1-3,5
/novel-merge 主项目 子项目1 子项目2
/novel-split 1-3 --length 2500 --name 第一部
/novel-tips 开头
/novel-trope 身份揭秘
```

恢复默认只预览，明确指定 `--apply` 才执行；执行前保留恢复前快照，额外文件不会被删除。恢复按文件原子替换，并非整项目事务；I/O 失败时可使用恢复前快照处理。差异比较按文件哈希列出变化，不是逐行 diff。合并/拆分生成项目「整理」目录下的新文件，不自动统一角色设定或重排原正文；拆分按 Unicode 字符目标硬切，可能跨句。

## 实际行为与边界

写作、审校、冲突、节奏、虚拟读者、市场等命令会把任务和文件路径交给当前会话的模型。命令返回「已提交」表示任务排队成功，报告和正文需由模型后续生成；评分与读者反应属于模型判断，不是客观测量或真实读者测试。

市场分析使用经验性平台描述，未接入实时市场数据库。不得据此宣称真实读者规模、推荐概率或收益。技巧与套路工具提供模型生成的建议，不宣称内置了固定数量的资料库。

`--detailed` 直接读取正文，提供逐章字数、最短/最长章及成对引号内文字占比。此占比是明确规则下的文本统计，无法识别所有对话，更不是角色主动率、质量分或 AI 检测概率。

## 文件与持久化

每本书一个项目目录，包含 `项目.json`、`写作规范.md`、`完本流程.md`、`设定.md`、`角色.md`、`大纲.md`、`世界状态.md`、`伏笔.md`、`剧情树.md` 和 `正文/`。进度以文件为准，可跨会话、压缩和重启保留。生成工作流要求模型持续同步这些文件。
