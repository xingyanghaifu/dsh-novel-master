fix: commands crashed without followup; cwd resolved to install dir (1.6.3)

Audited all 33 commands by invoking each handler with the real host invocation
shape ({ commandId, agent, rawInput, attachments, signal }) instead of a test
double, which surfaced two real defects.

1. Four commands threw instead of running. /novel-continue, /novel-outline,
   /novel-cast and /novel-spark called agent.followup unconditionally, but the
   documented Agent interface is only { readonly id }. Missing the method threw
   "Cannot read properties of undefined (reading followup)" after the command had
   already done its work, so nothing was returned. Now probed, with a readable
   receipt and the prompt text when no hand-off exists.

2. Workdir resolution fell through to process.cwd(). The real invocation carries
   no cwd and the agent has no session property, so every command read and wrote
   relative to the installation directory rather than the workspace. agentCwd now
   falls back cwd -> session.header.cwd -> session.cwd -> workingDirectory.
   The guidance integration module used process.cwd() directly and now shares it.

Argument parsing widened; each case was silently ignored or corrupted the name:
- "第60章" left "第" and "60章节" left "节" in the project name, so the project
  was then never found
- full-width digits ("６０章") were not recognised at all
- "60章--auto" and "--auto" glued to a preceding word were not recognised,
  because the pattern demanded spaces on both sides
- added "-a" as a short form, and bracketed or quoted project names for pasted
  names

207 tests pass.
