# 路径验证防呆设计

## 功能概述

为 **项目目录（projectsDir）** 配置项增加了智能验证和修复功能，解决用户误填绝对路径、`.`/`..` 路径段、末尾空格等常见错误。

---

## 新增模块

### 1. **路径验证辅助库** (`src/path-helper.js`)

核心验证逻辑，提供：

#### **validateProjectDirectory(directory, cwd)**
- **输入**：用户输入的路径字符串 + 当前工作目录
- **输出**：验证结果对象
  ```js
  {
    valid: boolean,           // 是否有效
    normalized?: string,      // 规范化后的有效路径
    error?: string,          // 错误类型（absolute/dot-segment/trailing/invalid-char）
    message?: string,        // 错误详细说明
    suggestion?: string,     // 智能修复建议（绝对路径会提取相对部分）
    canAutoFix: boolean     // 是否可一键修复
  }
  ```

#### **智能修复规则**
| 问题类型 | 示例 | 自动修复为 |
|---------|------|-----------|
| 绝对路径 | `E:\dshwork\novels` | `novels` |
| 绝对路径 | `C:\projects\book\src` | `book\src` |
| `.` 或 `..` 段 | `./novels` | `novels` |
| `.` 或 `..` 段 | `../books` | `books` |
| 末尾空格/点 | `novels ` | `novels` |
| Windows 非法字符 | 无法自动修复，提示错误 |

---

### 2. **验证 API** (`src/index.js` 新增)

提供后端验证端点：

#### **POST /api/novel/validate-project-directory**
- **请求体**：
  ```json
  {
    "directory": "用户输入的路径",
    "cwd": "E:\\dshwork"
  }
  ```
- **响应**：与 `validateProjectDirectory()` 相同结构

#### **注册方式**
- 通过 `installPathValidationAPI(ctx, logger)` 挂载到 webServer
- 自动处理错误并返回 JSON 响应

---

### 3. **前端组件** (`client/components/ProjectDirectoryInput.vue`)

智能输入框组件，特性：

#### **实时验证**
- 输入时显示即时验证结果（✓ 有效 / ✗ 错误类型）
- 错误时高亮输入框（红色边框）

#### **智能提示**
- 显示错误原因和修复建议
- 示例：
  ```
  ✗ 不能使用绝对路径
  建议：novels（已提取相对部分）
  [一键修复] 按钮
  ```

#### **一键修复**
- 点击「一键修复」按钮自动填入建议值
- 无法自动修复的错误（如非法字符）只显示提示

#### **防抖处理**
- 输入停止 500ms 后才发起验证请求，减少服务器压力

### 4. **Schema 集成** (`src/index.js`)

为 `projectsDir` 配置项添加自定义组件：

```js
projectsDir: live(z.string().default('novel_projects'))

  .comment('小说项目存放的相对路径（相对于工作目录）')
  .meta({ component: 'ProjectDirectoryInput' }),  // ← 新增
```

### 5. **客户端注册** (`client/index.ts`)

注册自定义表单组件到 Cordis 设置系统：

```typescript
import ProjectDirectoryInput from './components/ProjectDirectoryInput.vue'

export default (ctx: Context) => {
  ctx.settings.component('ProjectDirectoryInput', ProjectDirectoryInput)
}
```

## 使用体验

### **场景 1：用户误填绝对路径**
1. 输入：`E:\dshwork\novel_projects`
2. 组件显示：
   ```
   ✗ 不能使用绝对路径
   建议：novel_projects
   [一键修复]
   ```
3. 点击「一键修复」→ 自动填入 `novel_projects`

### **场景 2：用户使用 `.` 开头**
1. 输入：`./novels`
2. 组件显示：
   ```
   ✗ 不能包含 . 或 .. 路径段
   建议：novels
   [一键修复]
   ```

### **场景 3：末尾多余空格**
1. 输入：`novels ` (末尾有空格)
2. 组件显示：
   ```
   ✗ 路径段不能以 . 或空白结尾
   建议：novels
   [一键修复]
   ```

### **场景 4：包含非法字符**
1. 输入：`novels<test>`
2. 组件显示：
   ```
   ✗ 包含 Windows 不允许的字符：<
   请移除非法字符后重试
   ```
   （无「一键修复」按钮，需手动修改）

## 技术亮点

### **防呆而非防错**
- 不直接拒绝输入，而是提供智能修复建议
- 用户体验友好，减少挫败感

### **零学习成本**
- 即时反馈，不需要查阅文档
- 修复建议清晰明了

### **健壮性**
- 后端验证防止绕过前端校验
- 命令执行前仍会检查路径合法性（双重保障）

### **性能优化**
- 防抖处理，避免频繁 API 请求
- 验证逻辑轻量级，响应迅速

---

## 配置迁移

现有用户无需手动迁移：

1. **已有合法配置**：正常使用，无变化
2. **已有非法配置**：
   - 命令仍会报错（保持一致性）
   - 打开设置页会看到错误提示和修复按钮
   - 一键修复后保存即可

## 开发者注意事项

### **扩展验证规则**
在 `src/path-helper.js` 中添加新的检查函数：

```js
export function validateProjectDirectory(directory, cwd) {
  // ... 现有检查 ...
  
  // 新增自定义规则
  if (directory.includes('禁止的关键词')) {
    return {
      valid: false,
      error: 'custom-rule',
      message: '包含禁止的关键词',
      canAutoFix: false
    }
  }
  
  // ...
}
```

### **自定义修复逻辑**
在相同函数中返回 `suggestion` 字段：

```js
return {
  valid: false,
  error: 'some-error',
  message: '错误说明',
  suggestion: '修复后的值',  // ← 提供建议
  canAutoFix: true
}
```

### **前端样式定制**
在 `ProjectDirectoryInput.vue` 的 `<style scoped>` 中修改：

```vue
<style scoped>
.input-error {
  border-color: #f56c6c;  /* 修改错误颜色 */
}
</style>
```
