# 项目目录验证：当前实现与限制

项目目录 `projectsDir` 必须是当前会话工作目录下的相对路径，例如 `novel_projects` 或 `books/fiction`。它与允许绝对路径的资料存储目录 `research.storageDir` 不同。

## 已实现

- 命令执行前通过严格验证，拒绝绝对路径、冒号、空字符、`.`/`..` 路径段和非法文件名字符。
- 每条命令保留自己的异步目录配置快照，多个并发任务互不覆盖。
- `validateProjectDirectory(directory, cwd)` 返回 `valid`、`normalized`、`error`、`errorType`、`message`，仅在可安全转换时提供 `suggestion`。
- 所有建议独立通过严格验证；工作目录外的绝对路径不会退化为最后一级目录名。
- 点路径段按原有路径语义规范化：`books/../archive` 的等价建议为 `archive`；`../archive` 不提供建议。
- `normalizeProjectDirectory()` 无法安全修正时保留输入并给出警告，不会重置到另一个默认目录。调用方应在采用建议前让用户确认。

## 前端状态

实际客户端入口为包根目录的 `client.js`。先前新增的 Vue 组件未接入该客户端，已移除；没有已上线的 500ms 防抖或自定义一键修复控件。普通设置表单与命令执行前的严格校验继续可用。

先前新增的 `/api/novel/validate-project-directory` 使用了宿主不支持的路由接口，也没有真实前端调用，已移除。现有经过宿主认证的 `/api/novel-master/` 设置和更新接口继续使用宿主的 `webServer.register()`。

Schema 不使用不受支持的 `.meta()` 方法。此方法曾导致插件在导入时失败。

## 检查示例

| 输入 | 处理 |
| --- | --- |
| `novel_projects` | 有效 |
| `books/fiction/` | 规范化为 `books/fiction` |
| `./books` | 命令严格拒绝；辅助库可建议等价的 `books` |
| `books/../archive` | 命令严格拒绝；辅助库可建议等价的 `archive` |
| `../books` | 拒绝，不提供建议 |
| 当前工作目录内的绝对路径 | 严格拒绝；提供 cwd 后辅助库可建议等价相对路径 |
| 工作目录外的绝对路径 | 拒绝，不替换为 basename |
| `folder?/../../outside` | 拒绝，不自动移除字符 |

回归测试位于 `test/project-directory.test.js`。路径限制为词法路径限制；本轮未新增符号链接隔离机制。
